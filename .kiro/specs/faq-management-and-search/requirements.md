# FAQ管理・検索 要件書

## 背景と目的
HELPOは、社員が人事・総務に関する定型問い合わせを、自分の言葉で調べて自己解決できるAIヘルプデスクです。
本仕様では、FAQ（よくある質問とその回答）を管理し、社員が自然な言い回しでも目的のFAQにたどり着ける検索機能を定義します。

本機能の狙いは以下の3つです。

- **知識を正しく整備する**：管理者がFAQを登録・更新・削除できるようにし、社員に伝える情報を最新に保つ。
- **自分の言葉で探せる**：同じ意味でも違う言い回しで質問しても、適切なFAQを見つけられるようにする。
- **社内だけで動かす**：FAQデータや検索に使う表現を社内PCだけで処理し、外部のAIサービスには送らない。

対象環境は、WindowsのGPUなしPCでも動作する研修用の最小構成です。

## 対象範囲と隣接機能

### 本機能で行うこと
- FAQの登録、一覧表示、更新、削除
- FAQ操作を管理者に限定する権限管理
- FAQ質問文から社内PCで検索用の表現を作り、FAQの更新にあわせて検索用データも自動で整える
- 社員からの問い合わせに対し、FAQを似ている順に探し出して返す
- 十分に似ているFAQを「そのまま回答として提示できる候補」と判定する

### 本機能で行わないこと
- PDFやOffice文書など、一般文書の取り込みと検索
- AIによる回答文の自動作成
- 社員向けチャット画面の作り込み
- 質問履歴や利用状況の分析ダッシュボード
- 外部AIサービスへの問い合わせ

### 隣接する機能との関係
- **認証機能**を使い、管理者だけがFAQを編集できるようにします。
- **チャット機能**は本機能で探したFAQを使って社員に回答を見せますが、本機能自体は回答の自動生成やチャット画面を持ちません。
- 社員が使うメインの検索入口はチャット機能の画面です。

## 機能要件

### 1. FAQの登録・一覧・更新・削除
管理者が社員から寄せられる定型問い合わせとその回答を、FAQとして管理できるようにします。

| 番号 | 受け入れ条件 |
|------|-------------|
| 1.1 | 管理者が新しいFAQを作成すると、質問文と回答文が保存され、同じ質問文がまだ登録されていなければ新しいFAQ IDが返される。 |
| 1.2 | 管理者が既存FAQの質問文または回答文を更新すると、指定したFAQだけが変更され、最終更新日時が記録される。 |
| 1.3 | 管理者がFAQを削除すると、該当FAQが完全に削除され、検索用データも一緒に整えられる。 |
| 1.4 | 質問文または回答文が未入力の場合、保存をやめて入力エラーを知らせる。 |
| 1.5 | FAQ一覧画面には、登録済みFAQの質問文と最終更新日時が表示される。 |

### 2. FAQ操作の権限管理
FAQの作成・変更・削除は管理者だけに許可し、誰でも書き換えられるリスクを防ぎます。

| 番号 | 受け入れ条件 |
|------|-------------|
| 2.1 | FAQの作成・更新・削除を要求されたとき、認証機能が提供する管理者判定を使って、ログイン中の利用者が管理者かどうか確認する。 |
| 2.2 | ログインはしているが管理者でない場合、FAQの作成・更新・削除を拒否し、権限が足りないことを知らせる。 |
| 2.3 | 未ログインの利用者がFAQ管理画面や管理用の処理にアクセスした場合、ログインを求め、データは返さない。 |
| 2.4 | 認証機能が定める「認証が必要」「権限が不足」の応答ルールに従う。 |
| 2.5 | 管理者判定のルールは各所で作り直さず、認証機能の提供する判定を呼び出す。 |

### 3. 社内PCでの検索用表現作成と検索データの整備
FAQの質問文から検索用の表現を作り、FAQの変更にあわせて検索データも最新に保ちます。これにより、自然な言い回しでも検索が効くようになります。

| 番号 | 受け入れ条件 |
|------|-------------|
| 3.1 | 新しいFAQが保存されたとき、質問文から社内PCで検索用の表現を作り、一緒に保存する。 |
| 3.2 | FAQの質問文が更新されたとき、古い検索用表現を入れ替え、検索データを更新する。 |
| 3.3 | FAQが削除されたとき、対応する検索用表現も削除する。 |
| 3.4 | アプリ起動時にFAQデータと検索用データがずれていることが分かった場合、ずれを直して検索データを作り直す。 |
| 3.5 | FAQの文や検索用表現を、外部のAIサービスに送信しない。 |
| 3.6 | 検索用表現の作成は、WindowsのCPUだけで動作し、GPUを必須としない。 |
| 3.7 | 使用するモデルのライセンスは、実際に選定する際に改めて確認し、ライセンス未確認のモデルを勝手に選ばない。 |

### 4. 自然な言い回しでのFAQ検索と回答提示判定
社員が自然な言葉で質問しても、意味の近いFAQを探し出します。十分に似ている場合は、そのまま回答として提示できる候補とします。

| 番号 | 受け入れ条件 |
|------|-------------|
| 4.1 | ログイン中の社員が自然な問い合わせを送ると、社内PCで作った検索用表現を使って、似ているFAQを順に返す。 |
| 4.2 | 返す候補には、FAQのID、質問文、回答文、そして「どれだけ似ているか」を示すスコアを含める。 |
| 4.3 | 最も似ている候補があらかじめ定めた判定基準を満たす場合、そのFAQを「回答として提示できる候補」とする。 |
| 4.4 | どの候補も基準を満たさない場合、「該当する回答が見つからない」ことを示す応答を返す。管理者が検索品質を確認できるよう、回答には使わない候補を診断情報として添えてもよい。 |
| 4.5 | 検索対象はFAQのみとし、他の文書や外部知識は含めない。 |

### 5. 最小構成での動作条件
外部サービスや高性能な機器に頼らず、社内の研修環境ですぐに使えるようにします。

| 番号 | 受け入れ条件 |
|------|-------------|
| 5.1 | 外部AIサービスへのネットワーク接続を必須としない。 |
| 5.2 | FAQの保存、検索用表現の作成、FAQの類似検索をすべて同一のローカルPC上で完結させる。 |
| 5.3 | 検索結果を直接回答として返すだけの簡易な仕組みとし、AIによる回答文生成は含めない。 |
